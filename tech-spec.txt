1. ОБЩИЕ СВЕДЕНИЯ
======================================================================
SmartPlan — веб-приложение для планирования и учёта работ Управления
бытовых и районных газовых сетей (УБиРОГС) УП «МИНГАЗ» (Минск, РБ).

Ключевые особенности:
 - работает БЕЗ сервера: открывается напрямую из файла (file://)
   или с любого статического хостинга (Netlify, общая сетевая папка);
 - все данные хранятся локально в браузере (localStorage);
 - поддержка многопользовательской работы через общую папку (NAS)
   с синхронизацией по файлу smartplan-db.json каждые 5 секунд;
 - мобильный и десктопный интерфейс (адаптивный);
 - все карты на Яндекс.Карты JS API 2.1 + OSM/2ГИС в сферической
   проекции.


2. ЦЕЛИ ПРОЕКТА
======================================================================
2.1. Планирование работ мастеров и слесарей на день/год.
2.2. Учёт выполненных работ (статусы, дедлайны, погода).
2.3. Визуализация объектов и маршрутов на карте.
2.4. Годовые графики работ с периодичностью и отклонениями.
2.5. Справочники: участки, виды работ, объекты (ГРП/ШРП/ГРС/ПГРП),
     пользователи, работники, нормы времени.
2.6. Отчёты и экспорт в Excel.


3. СТЕК ТЕХНОЛОГИЙ
======================================================================
Фронтенд (только):
 - HTML5 + CSS3 (custom properties: --card, --line, --ink и др.)
 - Vanilla JavaScript (ES5/ES2015), без сборщиков
 - Яндекс.Карты API 2.1 (ymaps.Map, Layer, GeoObject, projection)
 - OSM (tile.openstreetmap.de) и 2ГИС — как подложки
 - Open-Meteo API — прогноз погоды (без ключа)
 - RainViewer API — радар осадков (tilecache.rainviewer.com)
 - OSRM Trip API — расчёт маршрутов (публичный)
 - SheetJS (xlsx.full.min.js) — обычный Excel-экспорт
 - SheetJS-style (xlsx.style.js) — Excel с цветами (графики)
 - Nominatim (OpenStreetMap) — геокодинг

Хранилище:
 - localStorage браузера (привязка к origin: файл или хост)
 - sessionStorage (кэш OSRM)
 - IndexedDB (память о выбранной папке синхронизации)
 - Файл smartplan-db.json в общей папке (при синхронизации)

Бэкенд (опционально, для будущей миграции):
 - Node.js + Express + PostgreSQL (Render)

5. МОДУЛИ СИСТЕМЫ
======================================================================

5.1. АВТОРИЗАЦИЯ И СЕССИИ
-------------------------
- Экран входа: логин + пароль (хэш SHA-256 при сиде).
- Сессия в localStorage: smartplan_session (id пользователя) +
  smartplan_logged_in='1' (флаг явного входа).
- Кнопки автозаполнения на экране входа (admin/seogs/master/slesar).
- Выход: очистка сессии, возврат на экран входа.
- Предупреждение о хранилище: если localStorage недоступен (Edge
  file://, приватный режим) — подменяется на in-memory shim с
  предупреждением на логине.

5.2. ПАНЕЛЬ МОНИТОРИНГА (ДАШБОРД)
---------------------------------
- Сводка на сегодня: задачи по мастерам, статусы (план/выполнено/
  просрочено/перенесено), часы/км.
- Гант-диаграмма дня мастера (выезд с базы в 8:30, порядок объезда
  «ближайший сосед» + OSRM-кэш).
- Быстрый переход к календарю, картам, графику.

5.3. ПЛАНИРОВАНИЕ / КАЛЕНДАРЬ
------------------------------
- Вид на день/неделю/месяц: сетка ячеек.
- Каждая ячейка — карточка задачи: время, адрес, работа, мастер,
  цвет по статусу (done/просрочено/дедлайн<=2дн/план).
- Drag&drop задач между днями.
- Создание задачи: объект + работа + дата + объём + слесаря.
- Задачи из графика работ (связь по graphId/graphRi/graphSid).
- Дедлайн = дата по графику + отклонение (в днях).
- Чекбокс «вне плана» в карточке задачи.
- Импорт/экспорт в Excel, импорт из Excel-шаблона.

5.4. КАРТА МАРШРУТОВ
--------------------
- Яндекс.Карта с тайлами (сферическая проекция sphericalMercator).
- Точки заданий на день, база УБиРОГС (центр), линия маршрута.
- Оптимизация порядка:
   а) Яндекс.Роутер (при наличии yandexApiKey в config.js);
   б) OSRM Trip (public server) с многостартовой оптимизацией.
- Пробки (Яндекс.Пробки): цветовой сэмплинг тайлов (зелёный/жёлтый/
  красный) → коэффициент к времени переезда; при недоступности —
  время без пробок.
- Калибровка: 1.39× к времени OSRM ≈ время Яндекса (эмпирически).
- Кнопка «↗ Яндекс.Карты» (открывает маршрут на yandex.ru/maps с
  координатами точек).
- Слой «Пробки» по кнопке (по умолчанию выкл).
- 3D-вождение (drive3d.html): модель машины, управление клавишами.

5.5. КАРТА МЕСТОПОЛОЖЕНИЯ (LiveMap)
------------------------------------
- Расписание на день: объекты, время прибытия, километраж между
  точками (из OSRM-кэша, тот же ключ что у дашборда).
- Полилиния маршрута, маркеры с номерами.
- DOM-тултипы (НЕ балуны Яндекса) — паттерн «прозрачный + единый
  map-click + div-подсказка».
- Погода в точках (Open-Meteo, без ключа).

5.6. КАРТА ОБЪЕКТОВ
-------------------
- Подложки (переключаются):
   • Яндекс (web_mercator-рендерер Яндекса);
   • OSM (tile.openstreetmap.de — зеркало, основной сервер блокирует);
   • 2ГИС (tile1.maps.2gis.com).
- Все подложки в одной проекции sphericalMercator (выровнены).
- Типы объектов: ГРП (синий), ШРП (фиолетовый), ГРС (бирюзовый),
  ПГРП (оранжевый), зоны (полигоны), прочие.
- Фильтр слоёв (тип + поиск по номеру/адресу).
- Клик по точке/области → DOM-тултип (без балунов).
- Подсказка «© Яндекс.Карты» скрыта CSS.
- Подложки: панель #om-basemap в правом верхнем углу.

5.7. СПРАВОЧНИКИ
----------------
5.7.1. Участки (area): название, цвет, мастер.
5.7.2. Виды работ (work_db.js, schema 5):

5.7.4. Нормы времени: привязка работы → участок (норма в ч/единицу).

5.11. ГРАФИК РАБОТ (годовой)
------------------------------
Страница «График работ» (в подменю «Планирование / Календарь»).

Структура графика:
  {id, name, year, respId, respName, created, works:[], objs:[...],
   area, workColors:{wid: hex}}

Объект в графике:
  {oid, type, name, works:[{sid, wid, period, dev, first,
                            occs:[{date, tid, wid}]}],
   hide, pastTasks, respId, respName}

Генерация задач:
  - периодичность «1 месяц» и отклонение 2 дня = дата + 1 мес - 2 дн
    (18.01 → 16.02).
  - дедлайн = дата работы + отклонение (в днях).
  - при создании задачи в планирование — к бригаде мастера добавляются
    его слесаря (wkBrigadeOf).
  - «вне плана» = чекбокс в карточке задачи.

Интерфейс:
  - Таблица объекты × месяцы (sticky колонка).
  - Клик по ячейке объекта/месяца → календарь дат.
  - Подсказка по треугольнику: работа/объект/дата/мастер/✔.

Панель инструментов:
  - Слева: + добавить объекты, периодичность, обозначения работ.
  - Справа: фильтр, печать, удалить работы.
  - Центр: год + ответственный (чипы), наименование.

Окно периодичности:
  - Несколько работ на объект («+ работа»).
  - Чекбокс «Добавлять задачи на прошедшие дни».
  - Удаление работы (×), редактирование period/dev/first.

Обозначения работ:
  - Цвет треугольника выбирается (input type=color).
  - Палитра: 16 цветов по умолчанию (gwColorOf).

Печать:
  - Модал: чекбоксы «Треугольники / Наименования / Даты».
  - Кнопка « Печать» → окно A4 landscape (год над месяцами).
  - Кнопка «📥 Excel» → выгрузка в Excel:
      * лист «График YYYY»: объекты × работы × 12 месяцев,
        треугольники цветом работы из «Обозначений»;
      * лист «Обозначения»: легенда цветов;
      * ячейки объекта/адреса объединены.
  - Треугольники ▲ и ☒ окрашиваются цветом работы (xlsx-js-style).

Фильтр: скрыть объекты (ob.hide) — не печатаются, не выгружаются.

5.14. ТЕСТ ПОГОДНЫЙ (wxtest)
------------------------------
Отдельная страница «Администрирование → Тест погодный», только admin.

Содержимое:
  - Карта осадков на СУТКИ текущего дня (00:00–23:00).
  - Радар RainViewer (последние 2 часа, кэш в localStorage весь день).
  - Модель Open-Meteo (сетка 9×11 = 99 точек, шаг 6–8 км) — остальные
    часы суток; дождь и снег разными цветами.
  - Ползунок 24 часа (метки 00..23, текущий час жирный).
  - Play-кнопка ▶ прокручивает сутки.
  - Клик по карте → DOM-окошко с погодой на выбранный час
    (температура, ветер м/с + направление, описание WMO, осадки).
  - Крестик ✕ закрывает окошко; при уходе со страницы — автозакрытие.
  - Легенда: линии границ г. Минск и Минского района (OSM relation
    59195/59190, SVG-слой ymSvgLayer), шкалы «Дождь» / «Снег».
  - Кнопка «↗ Яндекс.Осадки» (внешняя ссылка).

Технически:
  - ymSvgLayer: полигоны, точки, blob (пятна осадков, радиальный
    градиент, радиус в метрах, пересчёт в пиксели по зуму).
  - RainViewer тайлы: /512/{z<=7}/{x}/{y}/2/1_1.png (схема 2,
    снег отдельными цветами), выше z7 — растяжка (getTileUrl/
    getTileSize, паттерн из доки ymaps.Layer).
  - Кэш радара: localStorage.smartplan_wx_radar_cache = {date, hours}.


6. СИНХРОНИЗАЦИЯ НЕСКОЛЬКИХ ПОЛЬЗОВАТЕЛЕЙ (БЕЗ СЕРВЕРА)
======================================================================
6.1. Архитектура
----------------
- Файл smartplan-db.json в общей сетевой папке (NAS).
- Каждый браузер подключается к файлу один раз (showOpenFilePicker).
- Цикл: каждые 5 сек — прочитать файл → слить изменения → записать
  (атомарно через FileSystemFileHandle.createWritable).
- Доступ к файлу сохраняется в IndexedDB (smartplan-sync).

6.2. Формат файла
-----------------
{
  "app": "SmartPlan",
  "v": 1,
  "ts": <timestamp>,
  "sections": {
    "smartplan_tasks_db":    {"records":{id:obj}, "rev":{id:n},
                              "tomb":{id:n}},
    "smartplan_objects_db":  {...},
    "smartplan_users_db":    {...},
    "smartplan_areas_db":    {...},
    "smartplan_workers_db":  {...},
    "smartplan_work_catalog": {...},
    "smartplan_graphs":      {...}
  }
}

6.3. Алгоритм слияния
----------------------
Для каждой записи (по id):
  - локальная ревизия = max(updated_at, предыдущая_ревизия+1);
  - если запись исчезла локально — надгробие (tombstone) с timestamp;
  - если удалена удалённо — запись удаляется локально;
  - иначе побеждает версия с более высокой ревизией;
  - если обе новее друг друга — выбираем более свежую (по updated_at
     или по времени правки).
Надгробия хранятся 30 дней, затем стираются.

6.4. Подключение пользователя
------------------------------
1. Скопировать smartplan-db.json в общую папку.
2.  → «📂 Открыть файл базы…» → выбрать файл → «Разрешить»
   в запросе браузера.
3. Запасной путь: перетащить файл в окно 🔄 из проводника.

6.5. Защита от потери данных
------------------------------
- При смене схемы БД (обновление кода): данные переносятся,
  прежний снимок → smartplan_prev_<KEY>.
- Автоснимок при входе → smartplan_autobackup.
- Кнопки: «💾 Бэкап базы» (JSON), « Восстановить» (из JSON),
  «🧪 Демо-данные» (12 объектов + 4 слесаря + задачи + график).

8. ИНТЕГРАЦИИ И ВНЕШНИЕ API
======================================================================

  OSRM Trip (оптимизация): /trip/v1/driving
- OSM Nominatim (геокодинг): https://nominatim.openstreetmap.org/
- Overpass API: https://overpass-api.de/api/interpreter (границы).

11. ОГРАНИЧЕНИЯ И НЮАНСЫ
======================================================================
11.1. Яндекс.Карты:
  - mapType принимает только ФАБРИКИ слоёв (не экземпляры);
  - projection: sphericalMercator для OSM/2ГИС;
  - Никаких балунов — только DOM-тултипы (анти-зависание);
  - Официальный рендерер для web_mercator:
    https://core-renderer-tiles.maps.yandex.net/tiles?l=map&
    lang=ru_RU&projection=web_mercator&x=%x&y=%y&z=%z&scale=1;
  - Тайлы радара RainViewer работают только до z7;
  - Яндекс.Осадки (nowcast) не встраиваются — платный GraphQL API
    с нестандартной сеткой; только внешняя ссылка.

11.2. RainViewer:
  - Бесплатный API отдаёт только радар за последние 2 часа;
  - Прогноз (nowcast) в бесплатном тарифе отключён;
  - Максимальный зум радарных тайлов = 7 (выше — заглушка
    «zoom level not supported»).

11.3. OSRM:
  - Публичный сервер — throttle (пауза 250 мс между запросами);
  - Без ключа: время без учёта пробок (калибровка × 1.39 ≈ Яндекс);
  - Пробки Яндекса встраиваются слоем, но публичных тайлов нет —
    при их отсутствии время даётся без пробок.

11.4. Edge/Chrome file://:
  - localStorage доступен, но при включённой «защите» может быть
    недоступен — используется in-memory shim;
  - File System Access API доступен (secureContext = true).

11.5. Firefox:
  - File System Access API НЕ поддерживается — синхронизация через
    общую папку недоступна (только обмен файлами бэкапа).


12. КЛЮЧЕВЫЕ ФУНКЦИИ И АЛГОРИТМЫ
======================================================================
- gwNextISO(iso, period, dev): дата + period мес - dev дней.
- gwMonthTriangles(g, ob, mi): все работы объекта за месяц.
- graphSeriesFind / graphSeriesOnMove / graphSeriesOnCreate — серии.
- gwColorOf(g, wid): цвет работы (из workColors или палитра).
- gwDoneMark(size, color): квадрат с крестом (цвет работы).
- gwTriangle(color, size): треугольник (SVG).
- ymSvgLayer(map, holder): SVG-слой поверх Яндекс.Карт (poly/dot/blob).
- omPointInPoly(lat, lng, poly): точка внутри полигона.
- lmNearestOrder(pts, base): порядок «ближайший сосед».
- lmOrderByWaypoints: переупорядочивание по OSRM-ответу.
- lmSchedCore: расписание по маршруту (drive/stay).
- tJamFactor(r,g,b,a): коэффициент пробок по цвету пикселя.
- wxtOmColor(pr, sf): цвет пятна осадков.
- mergeCycle(fileData): слияние двух версий базы.

14. ДЕПЛОЙ
======================================================================
Варианты:
1) Локальная папка на NAS: копируется uploads/ целиком, открывается
   index.html через file:// или через встроенный http-сервер.
2) Netlify (фронтенд): uploads/ загружается как статика.
3) Render (бэкенд, опционально): backend/ деплоится как Node.js-
   приложение; при наличии сервера useServerApi=true и данные
   синхронизируются через Supabase/PostgreSQL.
4) Общая папка NAS: файл smartplan-db.json синхронизирует браузеры.


15. КРИТЕРИИ ПРИЁМКИ
======================================================================
- Все 12 экранов открываются, не падают при смене роли.
- CRUD задач/объектов/работ/пользователей работает офлайн.
- Календарь: drag&drop, статусы, дедлайны.
- Карты: все 3 подложки, переключение, клик, тултипы.
- Маршрут: оптимизация, линия, время, «↗ Яндекс.Карты».
- График: генерация задач, периодичность, обозначения, печать,
  Excel с цветными метками, легенда.

  границы Минска/района.
- Синхронизация: 2 браузера, обмен задачами/объектами/графиками,
  удаления передаются, правки сливаются по ревизиям.
- Демо-данные: 12 объектов, 4 слесаря, 9 задач, график — без дублей
  при повторном запуске.
- Бэкап/восстановление: скачивается JSON, восстанавливается из JSON.
- Смена схемы БД: данные не теряются, есть снимок prev_.
- Маркеры версии обновлены во всех трёх местах.
